# SPEC-WATCHLIST-001: Acceptance Criteria

**TAG BLOCK**: SPEC-WATCHLIST-001 | Watchlist Management | 2026-02-22 | In Progress | High

## 테스트 시나리오 (Test Scenarios)

### Given-When-Then 형식

#### 시나리오 1: 사용자가 관심 종목 페이지에 접속한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 기존에 종목을 조회한 이력이 있다

**When** (이벤트):

- 사용자가 내비게이션 메뉴에서 "관심 종목"을 클릭한다

**Then** (예상 결과):

- 관심 종목 페이지가 로딩된다
- 세 개의 탭(최근 조회, 전체, 그룹별)이 표시된다
- "최근 조회" 탭이 기본적으로 활성화된다
- 최근 조회 목록에 최대 20개의 종목이 표시된다
- 각 종목 카드에 종목명, 코드, 현재가, 등락, 등락률이 표시된다
- 상승 종목은 빨간색, 하락 종목은 파란색, 보합은 회색으로 표시된다

**에지 케이스**:

- 최근 조회 이력이 없는 경우: "최근 조회한 종목이 없습니다" 메시지 표시

---

#### 시나리오 2: 사용자가 종목을 관심 종목에 추가한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 종목 검색 결과 페이지에 있다
- 해당 종목이 아직 관심 종목에 없다

**When** (이벤트):

- 사용자가 종목 카드의 "관심 종목 추가" 버튼을 클릭한다

**Then** (예상 결과):

- "관심 종목에 추가되었습니다" toast 메시지가 표시된다
- 버튼이 "관심 종목에서 제거"로 변경된다
- "전체" 탭과 "그룹별" 탭에서 해당 종목을 볼 수 있다
- 추가된 종목이 목록의 맨 위에 표시된다

**에지 케이스**:

- 이미 추가된 종목인 경우: "이미 추가된 종목입니다" 메시지 표시
- 네트워크 오류 발생 시: "추가에 실패했습니다. 다시 시도해주세요" 에러 메시지 표시

---

#### 시나리오 3: 사용자가 최근 조회 목록을 확인한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 최근 3일 내에 10개의 종목을 조회했다

**When** (이벤트):

- 사용자가 관심 종목 페이지의 "최근 조회" 탭을 클릭한다

**Then** (예상 결과):

- 최근 조회한 10개의 종목이 조회 역순으로 표시된다
- 각 종목 카드에 종목명, 코드, 마지막 조회 시간이 표시된다
- 종목 카드를 클릭하면 종목 상세 페이지로 이동한다
- 조회 시간은 "N시간 전", "N일 전" 형식으로 표시된다

**에지 케이스**:

- 최근 조회 이력이 없는 경우: "최근 조회한 종목이 없습니다" 메시지 표시
- 50개를 초과하는 경우: 가장 오래된 항목이 자동 삭제됨

---

#### 시나리오 4: 사용자가 그룹을 생성하고 관리한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 관심 종목 페이지의 "그룹별" 탭에 있다
- 사용자는 "국내주식", "해외주식" 그룹을 가지고 있다

**When** (이벤트):

- 사용자가 "그룹 관리" 버튼을 클릭한다
- "새 그룹" 버튼을 클릭한다
- "ETF"라는 그룹 이름을 입력하고 "생성"을 클릭한다

**Then** (예상 결과):

- "그룹이 생성되었습니다" 메시지가 표시된다
- 그룹 관리 모달에 "ETF" 그룹이 추가된다
- "그룹별" 탭에 "ETF" 섹션이 표시된다
- 새 그룹은 아직 종목이 없어 "종목이 없습니다" 메시지를 표시한다

**에지 케이스**:

- 그룹 이름이 중복되는 경우: "이미 존재하는 그룹입니다" 에러 메시지 표시
- 그룹 이름이 100자를 초과하는 경우: "그룹 이름은 100자 이하여야 합니다" 에러 메시지 표시

---

#### 시나리오 5: 사용자가 관심 종목을 삭제한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 관심 종목에 5개의 종목을 가지고 있다
- 사용자는 "전체" 탭을 보고 있다

**When** (이벤트):

- 사용자가 종목 카드의 "삭제" 버튼을 클릭한다
- 확인 모달에서 "삭제"를 클릭한다

**Then** (예상 결과):

- 종목 카드가 즉시 목록에서 제거된다
- "관심 종목에서 삭제되었습니다" 메시지가 표시된다
- 남은 4개의 종목이 표시된다
- "그룹별" 탭에서도 해당 종목이 제거된다

**에지 케이스**:

- 확인 없이 삭제하는 경우: 되돌릴 수 없음을 명시하는 경고 메시지 표시
- 네트워크 오류 발생 시: "삭제에 실패했습니다. 다시 시도해주세요" 에러 메시지 표시

---

#### 시나리오 6: 사용자가 관심 종목을 다른 그룹으로 이동한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 "국내주식" 그룹에 "삼성전자" 종목을 가지고 있다
- 사용자는 "ETF" 그룹을 생성했다

**When** (이벤트):

- 사용자가 "삼성전자" 종목 카드의 "그룹 변경" 버튼을 클릭한다
- 드롭다운에서 "ETF"를 선택한다

**Then** (예상 결과):

- "그룹이 변경되었습니다" 메시지가 표시된다
- "국내주식" 그룹에서 "삼성전자"가 제거된다
- "ETF" 그룹에 "삼성전자"가 추가된다
- "전체" 탭에서는 여전히 "삼성전자"를 볼 수 있다

**에지 케이스**:

- 그룹 변경 실패 시: 원래 그룹에 종목 유지, 에러 메시지 표시

---

#### 시나리오 7: 사용자가 관심 종목 순서를 변경한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 "국내주식" 그룹에 5개의 종목을 가지고 있다
- 현재 순서: A, B, C, D, E

**When** (이벤트):

- 사용자가 종목 C를 드래그하여 A 위에 놓는다

**Then** (예상 결과):

- 새로운 순서: C, A, B, D, E
- 변경 사항이 즉시 데이터베이스에 저장된다
- 페이지를 새로고침해도 순서가 유지된다

**에지 케이스**:

- 드래그 앤 드롭이 지원되지 않는 환경: 화살표 버튼으로 순서 변경 대체 제공

---

#### 시나리오 8: 사용자가 관심 종목을 검색한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 50개의 관심 종목을 가지고 있다
- 사용자는 "전체" 탭을 보고 있다

**When** (이벤트):

- 사용자가 검색 바에 "삼성"을 입력한다

**Then** (예상 결과):

- "삼성"을 포함하는 종목만 표시된다 (예: 삼성전자, 삼성SDI, 삼성물산)
- 검색 결과 개수가 표시된다 (예: "3개의 종목")
- 검색어를 지우면 모든 종목이 다시 표시된다

**에지 케이스**:

- 검색 결과가 없는 경우: "검색 결과가 없습니다" 메시지 표시
- 특수문자 검색: 안전하게 처리, SQL 인젝션 방지

---

#### 시나리오 9: 시스템이 실시간 가격을 업데이트한다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 관심 종목 페이지에 있다
- 현재 시간은 10:00:00이다

**When** (이벤트):

- 30초가 경과한다 (10:00:30)

**Then** (예상 결과):

- 가격 정보가 자동으로 새로고침된다
- 변경된 가격이 있으면 애니메이션으로 표시된다
- "마지막 업데이트: 방금 전" 메시지가 표시된다

**에지 케이스**:

- KIS API 호출 실패 시: "가격 업데이트에 실패했습니다. 마지막으로 저장된 가격을 표시합니다" 메시지 표시
- 네트워크 지연 시: 로딩 스피너 표시

---

#### 시나리오 10: 사용자가 관심 종목을 CSV로 내보낸다

**Given** (사전 조건):

- 사용자가 로그인되어 있다
- 사용자가 10개의 관심 종목을 가지고 있다

**When** (이벤트):

- 사용자가 "내보내기" 버튼을 클릭한다
- "CSV" 형식을 선택한다

**Then** (예상 결과):

- CSV 파일이 다운로드된다
- CSV 파일에는 종목 코드, 종목명, 그룹, 추가 일자, 현재가, 등락률이 포함된다
- 파일명은 "watchlist-YYYY-MM-DD.csv" 형식이다

**에지 케이스**:

- 관심 종목이 0개인 경우: "내보낼 종목이 없습니다" 메시지 표시
- CSV 생성 실패 시: "내보내기에 실패했습니다. 다시 시도해주세요" 에러 메시지 표시

## 품질 게이트 (Quality Gates)

### 기능적 요구사항 (Functional Requirements)

**필수 조건**:

- [ ] 모든 EARS 요구사항이 충족됨
- [ ] 모든 API 엔드포인트가 정상 동작함
- [ ] 모든 UI 컴포넌트가 정상 렌더링됨
- [ ] 사용자별 데이터 분리가 완벽하게 동작함
- [ ] 중복 추가가 방지됨
- [ ] 삭제 작업이 안전하게 처리됨

**검증 방법**:

- E2E 테스트: Playwright로 모든 시나리오 실행
- API 테스트: 모든 엔드포인트에 대한 통합 테스트
- 수동 테스트: QA 팀이 정의된 테스트 케이스 실행

### 성능 (Performance)

**필수 조건**:

- [ ] 페이지 로드 시간: 2초 이내 (FCP)
- [ ] API 응답 시간: 500ms 이내 (P95)
- [ ] 실시간 업데이트 주기: 30초
- [ ] 100개의 관심 종목 렌더링: 1초 이내

**검증 방법**:

- Lighthouse CI: 성능 점수 90+ 달성
- WebPageTest: 페이지 로드 시간 측정
- 부하 테스트: k6를 이용한 API 부하 테스트

### 접근성 (Accessibility)

**필수 조건**:

- [ ] WCAG 2.1 AA 준수
- [ ] 키보드 내비게이션 지원
- [ ] 스크린 리더 호환성
- [ ] 색상 대비율 4.5:1 이상
- [ ] 포커스 표시 명확함
- [ ] ARIA 라벨 제공

**검증 방법**:

- axe DevTools: 자동 접근성 테스트
- WAVE: 웹 접근성 평가 도구
- 수동 테스트: 스크린 리더(NVDA, VoiceOver)로 테스트

### 보안 (Security)

**필수 조건**:

- [ ] 사용자별 데이터 분리 (Row-Level Security)
- [ ] SQL 인젝션 방지 (Prisma ORM)
- [ ] XSS 방지 (React 기본 보안)
- [ ] CSRF 방지 (NextAuth.js)
- [ ] 인증된 사용자만 접근 가능
- [ ] 민감 정보 로깅 안 함

**검증 방법**:

- OWASP ZAP: 보안 취약점 스캔
- Penetration Testing: 화이트 해커 테스트
- Code Review: 보안 전문가 리뷰

### 유지보수성 (Maintainability)

**필수 조건**:

- [ ] TypeScript 타입 안정성 100%
- [ ] ESLint 경고 0개
- [ ] 단위 테스트 커버리지 85% 이상
- [ ] E2E 테스트 커버리지 주요 시나리오 100%
- [ ] 코드 컨벤션 일관성
- [ ] 문화권에 맞는 주석 (한국어)

**검증 방법**:

- Vitest: 단위 테스트 및 커버리지 리포트
- Playwright: E2E 테스트 리포트
- ESLint/Prettier: 코드 품질 검사
- SonarQube: 코드 품질 분석

### 사용자 경험 (User Experience)

**필수 조건**:

- [ ] 직관적인 내비게이션
- [ ] 명확한 피드백 메시지
- [ ] 일관된 UI 패턴
- [ ] 반응형 디자인 (모바일/태블릿/데스크톱)
- [ ] 로딩 상태 표시
- [ ] 에러 상태 적절한 메시지

**검증 방법**:

- 사용자 테스트: 5명 이상의 실제 사용자 테스트
- A/B 테스트: UI 개선안 비교
- 피드백 수집: 사용자 만족도 조사

### 품질 게이트 통과 기준

**TRUST 5 Framework**:

- **Tested**: 단위 테스트 85%+, E2E 테스트 주요 시나리오 100%
- **Readable**: ESLint 경고 0개, 명확한 변수/함수 이름
- **Unified**: Prettier 포맷팅, 일관된 코드 스타일
